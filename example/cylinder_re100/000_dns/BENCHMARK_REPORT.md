## Analysis

### Why is GCC Faster?

1. **OpenBLAS vs MKL for Small Problems**
   - GCC links to OpenBLAS (`-lblas -llapack`)
   - Intel links to MKL (`-qmkl=sequential`)
   - MKL is optimized for large matrices; OpenBLAS excels at small/medium sizes
   - With only 76K gridpoints, MKL's dispatch overhead dominates

2. **Memory Efficiency**
   - GCC uses 46% less memory (0.86 GB vs 1.25 GB)
   - Less memory = better cache utilization
   - MKL allocates additional work buffers

3. **Data Movement Paradox**
   - ifx moves 45% more data (1.6 vs 1.1 GB/s)
   - But computes 31% fewer gridpoints
   - Indicates memory bandwidth bottleneck, not compute bottleneck

### Compiler Flags Used

**GCC:**
```
-O2 -cpp -fdefault-real-8 -fdefault-double-8 -w -std=legacy
-ffixed-form -ffixed-line-length-none -march=native -mcmodel=large
-fno-lto -lblas -llapack -lfftw3
```

**Intel (ifx/ifort):**
```
-O2 -fpp -r8 -fpconstant -fixed -extend-source -xHost
-mcmodel=large -qmkl=sequential
```

## Recommendations

### For Small Problems (< 500K gridpoints)
- **Use GCC + OpenBLAS** for best performance
- MKL overhead outweighs its benefits

### For Large Problems (> 1M gridpoints)
- Intel + MKL may be faster (untested at this scale)
- MKL's optimized algorithms shine with larger matrices

### For Portability
- GCC is more portable across systems
- No dependency on Intel runtime libraries

## Conclusions

For this 2D cylinder case at Re=100:

1. **GCC + OpenBLAS is the fastest option** (+31% over Intel)
2. **Memory efficiency matters** more than raw FLOPS for small problems
3. **MKL is overkill** for problems under ~500K gridpoints
4. **Both Intel compilers perform similarly** (ifx ~1% faster than ifort)

These results may differ for:
- 3D cases with larger grids
- Higher polynomial orders (lx1 > 10)
- Different CPU architectures (AMD, older Intel)
